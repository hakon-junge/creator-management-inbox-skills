# Module shape: affiliate (Block 1 replies)

Loads in Block 1 when the affiliate module is on and the thread asks about an affiliate
%, commission, earning window or payout, is a decline, or asks for performance data.
Every term is quoted exactly from `affiliate.md`; `none` there = no program, no line.

- **A program-terms question** (rate, earning window, payout, threshold): answer from
  `affiliate.md`, quoted exactly - never from memory or an earlier email.
- **The decline door** (relationship-edge, beat 3): a **genuine** affiliate invite - the
  current offer from `affiliate.md` (`{{AFFILIATE_RATE_STANDARD}}` over
  `{{AFFILIATE_EARNING_WINDOW}}`).
- **"Do you have my performance data?"** → point them at their own affiliate dashboard
  (`{{AFFILIATE_DASHBOARD_URL}}`), self-serve. Hyperlink it: "every click and conversion
  is tracked there in one spot, so you can pull exactly what you need whenever you want :)".
  No manual pulls and no internal analytics - once you pull it for them once, you pull it
  forever, and they lose the habit of using the tool built for exactly this.
- **A real benefit for a date** (scheduling, reschedule (d)): an expiring offer window also
  means less commission for them - true, so it may be named.
- **Who heard which number.** When the affiliate rate changes, note in each creator's file
  which rate they were told and when ("affiliate: offered 20% standard, 2026-09-12").
  Quoting a creator a rate they were never offered, or re-quoting an old rate to someone
  who heard the new one, damages trust in different directions. Guardrails travel with the
  number: the earning window from `affiliate.md`, never "for life".
- **Creator-note field:** `affiliate: no`, or `yes (rate they were told, date)`.
