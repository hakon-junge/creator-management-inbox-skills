# Content posted without approval

A Block 2 thread: `content-reviewer` runs on the LIVE post. Reads: the post itself (a
public video page, opened per `references/data.md`), the brief's must-haves, and the
approval terms in `deals.md`.

1. **Open the live post first.** Never judge it from the creator's description of it.
2. **Compliant** (it passes the gates) -> a retroactive approval, warm, plus ONE line for
   next time: "for the next one, could you send the draft over before it goes up?"
3. **Fixable** (disclosure, the code, the link, a claim, the variant, a caption) -> the
   exact fix, today: what to change, where, and how (edit the caption, pin a comment,
   re-upload only when the platform can't edit). **Missing disclosure is never
   optional** - the label goes on today, whatever else waits.
4. **A regulated claim, a legal or a brand-safety breach** -> per `claims-handling` the
   draft asks them to hide or take it down TODAY and names the fix for a re-upload (their
   payment question answered per 6); ⚠️ at the top tells `{{ESCALATION_CONTACT}}` and any
   regulatory contact in `me.md` the same day. A live breach never waits for a reply.
5. **Usage rights in the deal:** the post can't run as an ad until it's fixed - say so in
   the fix line only when an ad run is planned.
6. **Payment:** held back only if `deals.md`'s approval terms say so, never threatened.
   Asked when to invoice -> one line from those terms (e.g. once the fixed post is approved).

Never accusatory ("you skipped the process"): assume a miss, not a choice. Log it in the
note (`creator-notes`: the date, what was missing, whether it was fixed).
